# Задача 03. SEO-аудит и оптимизация (раз в неделю)

Цель: убедиться, что сайт технически чист и каждая страница наилучшим образом отвечает своему запросу. Менять только то, для чего есть основание. Не переписывать ради переписывания: поисковику нужно время, чтобы оценить изменения.

## Шаг 1. Технический аудит

1. `python3 build.py`, затем `python3 ops/tools/seo_audit.py docs`. Разбери каждую строку вывода.
2. Проверь дополнительно:
   - `docs/sitemap.xml` содержит все страницы из `src/pages` и все профили и разборы; нет 404 и страниц с `noindex`;
   - у каждой страницы один H1, уникальные title и description; title до ~68 знаков (длиннее сборка срезает название сайта), description 90–165 знаков;
   - canonical и Open Graph на месте, JSON-LD валиден (BreadcrumbList), у картинок alt, width, height;
   - внутренние ссылки: у каждой страницы не меньше двух входящих ссылок (кроме 404); новые профили и разборы связаны с каталогом и разборами;
   - вес страниц и картинок: не появилось ли картинок больше 150 КБ; нет внешних запросов (шрифты локальные);
   - мобильная версия в Playwright на 390 px: нет горизонтальной прокрутки.
3. Если в `site.json` задан `custom_domain`, проверь живой сайт через WebFetch: `robots.txt`, `sitemap.xml`, главная, 404 отдает статус 404.

## Шаг 2. Данные поиска (когда появятся)

- Если доступны инструменты встроенного браузера и пользователь подключила сайт к Яндекс Вебмастеру — открой Вебмастер (только чтение): «Поисковые запросы» (показы, клики, позиция), «Страницы в поиске», «Диагностика», «Безопасность и нарушения». Сохрани сводку в `ops/data/webmaster.json` с датой.
- Если Вебмастер недоступен — работай только с техническим аудитом и спросом из `ops/data/wordstat.json`; так и напиши в отчете.

## Шаг 3. Оптимизация с основанием

Допустимые основания для правки:
- техническая ошибка из шага 1;
- страница получает показы, но мало кликов (по данным Вебмастера) — правь title/description так, чтобы точнее отвечать запросу;
- по Вордстату основной запрос страницы сформулирован иначе, чем в title/H1 (например, люди ищут «цветок», а у нас только «растение»);
- в разделе нет ссылки на важную страницу.

Правила:
- Не больше 10 правок за запуск.
- Один и тот же title не меняй чаще раза в 30 дней. Веди лог `ops/data/seo-changes.json`: `[{"date": "…", "url": "…", "field": "title", "old": "…", "new": "…", "reason": "…"}]` и сверяйся с ним.
- Никакого переспама: ключ один раз в title, естественно в H1 и тексте. Не добавляй скрытый текст, списки запросов, «SEO-тексты».
- Не меняй адреса страниц (URL) без редиректа; на GitHub Pages редиректов нет — значит, адреса не меняем.
- Новых страниц эта задача не создает (это задачи 02 и 05).

## Шаг 4. Публикация и отчет

По `ops/RUNBOOK.md`. В отчете: что проверено, какие проблемы нашлись, что исправлено (было → стало, почему), что требует решения пользователя (например, подключить домен и Вебмастер).
